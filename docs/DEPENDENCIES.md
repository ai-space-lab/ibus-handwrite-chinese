## Notes

### onnxruntime — venv-only

`onnxruntime` is a large binary package (tens of MB) with many version-specific and platform-specific builds. It is installed in an isolated Python virtual environment at `/usr/local/share/ibus-handwrite-chinese/venv/` rather than as a system package. This avoids:

- Conflicts with other applications that need different onnxruntime versions
- Large dependency footprint in the system package manager
- Platform-specific build issues across distros

The venv uses `--system-site-packages` so the engine can access system-installed packages (evdev, gi, numpy, cairo) while keeping onnxruntime isolated.

**Correctly omitted from**: debian/control, RPM spec, PKGBUILD (installed via pip in post-install scripts). **Included in**: install.sh line 175, RPM spec %post (line 154), PKGBUILD .install (line 50).

### tomli — optional (stdlib >=3.11)

`tomli` is a backport of Python's `tomllib` module, added in Python 3.11. The engine's config loader (`src/handwrite_config.py`) tries `import tomllib` first, then falls back to `import tomli`. If neither is available, TOML config files are silently skipped and the engine uses defaults.

On Python 3.12+ (as probed — 3.12.3), `tomllib` is available in the stdlib, so `tomli` is never needed.

**Listed correctly as optional**: install.sh line 182 (pip install, wrapped in `|| true`). **Omitted correctly from**: all packaging files (pip-installed in venv).

### python3-cairo (pycairo) — missing from all packaging files

The engine imports `cairo` directly at multiple points (lines 135, 791, 835, etc.) for:
- Creating ImageSurface and Context for stroke rendering
- Font rendering for candidate text
- Line caps/joins/antialiasing

Despite being a hard runtime dependency, `python3-cairo` (Debian: `python3-cairo`, Fedora/Arch: `python-cairo`) is **not listed in any packaging file**. It is only listed in `bootstrap.sh` under all distros. If a user installs via `.deb` or `.rpm` directly (without bootstrap.sh), the engine will crash on launch with an `ImportError: No module named 'cairo'`.

On Debian, `python3-gi-cairo` provides `gi.repository.cairo` but NOT `import cairo` (that requires `python3-cairo`). Both packages happen to be installed on the test system.

**Recommendation**: Add `python3-cairo` (`python-cairo` on Arch) to:
- `packaging/debian/control` Depends field
- `packaging/ibus-handwrite-chinese.spec` Requires field
- `packaging/PKGBUILD` depends array

### unzip — unnecessary dependency

`unzip` is listed as a dependency in all packaging files (debian/control, RPM spec, PKGBUILD) and installed by install.sh and bootstrap.sh. However, no model or data files are distributed as zip archives — the ONNX model is downloaded as `.onnx` and the dictionary as `.txt`, both via `wget`. The `unzip` package is never referenced in the source code or install scripts.

**Recommendation**: Remove `unzip` from:
- `tools/install.sh` apt-get command (line 86)
- `packaging/debian/control` Depends field (line 21)
- `packaging/ibus-handwrite-chinese.spec` Requires field (line 23)
- `packaging/PKGBUILD` depends array (line 11)
- `bootstrap.sh` install commands (lines 66, 70, 74, 79)

### sha256sum — provided by coreutils, always available

`sha256sum` is part of GNU coreutils, which is present on every Linux system. No explicit packaging entry is needed.

### python3-venv — Debian-specific

`python3-venv` is a separate package on Debian/Ubuntu/Mint but is bundled into `python3-libs` on Fedora/openSUSE and into the `python` package on Arch. It is correctly:
- Listed in `debian/control` as a dependency
- Installed by `install.sh` for Debian family
- Installed by `bootstrap.sh` for Debian family
- Omitted from RPM spec (comment on line 19 documents this)
- Not needed in PKGBUILD (Arch bundles venv with python)

### Version constraints

The `>=1.21` constraint for numpy is conservative — numpy 1.26.4 is installed on the test system. The `>=1.15` constraint for onnxruntime is supported by the probed version 1.27.0. The `>=1.5` constraint for IBus is supported by the probed version 1.5.29-rc2. No strict version minimum exists for evdev or pycairo; the distro-packaged versions are assumed sufficient.

### sqlite3 — stdlib, no packaging needed

`sqlite3` is a Python standard library module. It is used for user dictionary storage (Wave 3 feature). No separate packaging dependency is required.
